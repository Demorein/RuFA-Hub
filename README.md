<h2 align="center">RuFA Hub</h2>

**RuFA Hub** — это локальная, расширяемая open source система для взаимодействия микроконтроллеров и серверов на аппаратном уровне. Предназначена для использования в промышленной среде и полностью независима от интернета.

<h2 align="center">📌 Основные особенности</h2>

- Поддержка любых микроконтроллеров (ESP8266, Wemos, Arduino и др.)
- Протокол MCIS (Microcontrollers Control and Interaction System)
- Веб-интерфейс на Flask, HTML, JavaScript
- Поддержка пользовательских HTML-страниц
- Хранение данных в SQLite
- Визуализация нагрузки (CPU, RAM, сеть)
- Расширяемая архитектура с модулями
- Поддержка CLI
- Полностью локальная работа без интернета

<h2 align="center">🧠 Архитектура</h2>

RuFA Hub построен на модульной архитектуре, что делает систему гибкой, расширяемой и легко адаптируемой под любые задачи.
🧩 Компоненты:

### 🖥️ RuFA Hub (RH) — серверная часть, работающая на базе Linux (рекомендуется Ubuntu). Она:

- Принимает, обрабатывает и маршрутизирует данные от устройств.

- Управляет подключёнными микроконтроллерами.

- Имеет встроенный CLI, SQLite базу данных и веб-интерфейс.

- Поддерживает работу с модулями, которые можно подключать для расширения логики.

### 📡 RuFA Connect (RC) — прошивка или лёгкое ПО для микроконтроллеров (например, ESP8266, Arduino с USB/Serial):

- Отправляет пакеты на RH с данными от датчиков или событиями.

- Получает команды от сервера (например, включить реле, изменить режим работы и т.д.).

- Может работать через UDP или Serial, в зависимости от реализации.

### 🧬 MCIS (Microcontrollers Control and Interaction System) — собственный протокол обмена:

- Основан на JSON-пакетах с обязательными ключами api, module и data.

- Позволяет гибко маршрутизировать данные от устройств к нужным модулям на стороне RH.

- Поддерживает буферизацию и отправку больших пакетов.

### 🔁 Взаимодействие:

- RC-устройство собирает данные (например, с датчиков) и формирует MCIS-пакет.

- Пакет отправляется на RH (через UDP, TCP или Serial).

- RH валидирует api, определяет module, и передаёт данные соответствующему обработчику.

- При необходимости RH отправляет ответ или команду обратно на RC.

### ⚙️ Особенности:

- Архитектура работает полностью локально, без зависимости от облаков.

- Обеспечивает высокую скорость отклика и надёжность, особенно в условиях промышленной эксплуатации.

- Легко масштабируется: можно подключить десятки или сотни RC-устройств без изменения базовой логики.



<h2 align="center">🌐 Веб-интерфейс </h2>

Веб-интерфейс RuFA Hub построен на Flask, с использованием HTML и JavaScript для отображения и интерактивности. Интерфейс полностью локальный и не требует подключения к интернету.
Основные разделы:

### 🔧 Hardware — отображает текущую нагрузку сервера:

- Использование CPU и RAM

- Температура процессора

- Активность сети

- История в виде графиков (данные сохраняются в SQLite)

### 🖥️ System — предоставляет сведения о системе:

- Имя хоста, uptime, архитектура

- Версия ОС и Python

- Настройки конфигурации RH

### 📟 Controllers — отображает подключённые микроконтроллеры:

- Вывод последних полученных данных

- Возможность отправки команд через интерфейс

- Указание статуса связи с устройством

### Дополнительные возможности:

- Пользовательские страницы — интерфейс поддерживает добавление собственных HTML-файлов:

- Можно отобразить данные с конкретного устройства (например, погоду, уровень воды, состояние реле)

Пример: можно вывести локальный интерфейс управления умным освещением или отображение графиков с температурных сенсоров

Интерфейс ориентирован на простоту и производительность — работает даже на слабом сервере (например, Raspberry Pi 4).

<h2 align="center">🔑 Работа с API-ключами </h2>

Система использует API-ключи для авторизации устройств, подключающихся к RuFA Hub через RuFA Connect. Это обеспечивает безопасность и контроль доступа.
### Как это работает:

- Каждый RC-устройствo при отправке данных должно включать api ключ в своём MCIS-пакете.

- RH проверяет, существует ли такой ключ в базе. Если нет — пакет отклоняется.

- Ключи хранятся в SQLite и привязаны к конкретному устройству или модулю.

### Как управлять:

- Через CLI:

- Генерация новых ключей

- Просмотр, удаление, перезапись существующих

### Через веб-интерфейс:

- Назначение ключа вручную

- Просмотр активных ключей и логов их использования

- Привязка описания к каждому ключу (например, “ESP в мастерской”)

### Пример:
```
{
"api": "123321123",
"module": "weather",
"data": "25.6°C"
}
```
Такой подход позволяет централизованно управлять устройствами и исключать неавторизованные подключения.

<h2 align="center">💻 CLI-интерфейс</h2>

CLI (Command Line Interface) в RuFA Hub предоставляет мощный инструмент для управления сервером без использования веб-интерфейса. Это особенно полезно для автоматизации, работы по SSH или в минимальных средах.
Примеры возможностей:

- Генерация и отзыв API-ключей для RuFA Connect

- Перезапуск отдельных модулей и всего MCIS-сервера

- Просмотр логов работы системы и конкретных модулей

- Мониторинг состояния устройств и их активности

- Отправка тестовых пакетов на модули

- Управление базой данных (очистка, экспорт, резервное копирование)

- Обновление конфигурации без перезапуска сервера

- Запуск режима отладки для MCIS-потока

- CLI-интерфейс RuFA Hub позволяет гибко управлять системой в условиях, когда графический интерфейс недоступен, и отлично подходит для системных администраторов и разработчиков.

<h2 align="center">🧩 Модули RuFA Hub</h2>

Модули — это настраиваемые обработчики входящих данных и событий в системе RuFA Hub. Каждый модуль работает как отдельный компонент и может выполнять любые действия на стороне сервера: от простых уведомлений до сложной логики с участием других систем.
Возможности модулей

Модули позволяют:

- Реагировать на входящие пакеты от RuFA Connect (RC)

- Отправлять ответы или команды обратно через протокол MCIS

- Взаимодействовать с внешними API (Telegram, Discord, HTTP и т.д.)

- Выполнять локальные действия (запись в базу, логирование, запуск скриптов)

- Использовать встроенные возможности RuFA Hub:

- Доступ к информации о CPU, RAM, GPU, сеть и другой статистике через модуль hardware

- Доступ к логам, графикам, конфигурациям устройств

- Отправку MCIS-пакетов на другие устройства прямо из модуля

### Пример реального использования

Во время тестирования RuFA Hub в полевых условиях был реализован модуль, интегрирующийся с Minecraft-сервером:

Был создан плагин, отправляющий HTTP-запрос на RuFA Hub при заходе игрока.

Сервер получал пакет через MCIS и направлял его в модуль mc_telegram_notify.

Модуль получал информацию об игроке и отправлял сообщение в Telegram через встроенного бота.

Результат: При заходе игрока в Minecraft приходило сообщение:

**🟢 Игрок Steve вошёл на сервер в 14:25 с IP 192.168.0.123.**

### Почему это удобно?

- Модули пишутся на **Python**, прямо внутри **RuFA Hub**.

- Они имеют доступ ко всем системным компонентам, включая API, базу данных, сетевые функции и внутренние данные.

- Можно использовать их как интерфейс автоматизации или прослойку интеграции с другими системами.

<h2 align="center">🗄️ SQLite база данных </h2>

RuFA Hub использует встроенную SQLite-базу данных для надёжного хранения и быстрого доступа к важным данным.
База данных используется для:

- Хранения истории графиков (нагрузка CPU, RAM, сеть и др.)

- Сохранения логов работы системы и модулей

- Конфигурации подключённых устройств и загруженных модулей

- Хранения API-ключей для RuFA Connect

- Сохранения информации о hardware-нагрузке и температуре

- Установки и хранения системных параметров

- Благодаря использованию SQLite данные сохраняются локально, без зависимости от внешних серверов или интернета, что повышает надёжность и безопасность.

<h2 align="center">📈 Графики и мониторинг</h2>

Система RuFA Hub обеспечивает удобный мониторинг ресурсов сервера и позволяет отслеживать ключевые метрики в режиме реального времени. Все данные автоматически сохраняются в базу данных для последующего анализа, визуализации и диагностики.
Отображаемые параметры:

- Загрузка CPU — позволяет контролировать, насколько активно задействован процессор.

- Использование RAM — отслеживает объём используемой оперативной памяти.

- Сетевое подключение — фиксирует входящий и исходящий трафик, скорость соединения.

- Температура компонентов (если доступно) — даёт представление о состоянии системы и необходимости охлаждения.

### Особенности:

- Данные собираются с заданной частотой и записываются в SQLite.

- Поддержка накопления и анализа истории метрик.

- Возможность отображения графиков за разные временные периоды (напр., последние 10 минут, час, сутки).

- Поддержка вывода на веб-интерфейс с автоматическим обновлением значений.

CLI и Web-интерфейс: позволяют работать с системой как локально (через терминал), так и удалённо (через браузер).


<h2 align="center">📦 Создание модулей для RuFA Hub </h2>

### 🧩 Что такое модуль?
Модуль в RuFA Hub — это обычный Python-файл, размещённый в директории modules/. Каждый такой модуль представляет собой логически изолированный обработчик данных, получаемых от MCIS через UDP, TCP или другие встроенные протоколы.

### ✅ Обязательные требования к модулю
Каждый модуль обязан содержать следующую функцию:

```
def mainloop(data: dict):
```
Пояснение:
Функция ```mainloop()``` вызывается автоматически RuFA Hub, каждый раз, когда на вход поступает новый пакет данных от MCIS.

В функцию передаётся аргумент data, представляющий собой словарь (dict), содержащий всю информацию из пакета.

В пакете обязательно должен присутствовать ключ "module", указывающий на имя модуля, который должен обработать данный пакет.

### 📥 Пример входящего пакета:
```
{
    "module": "temperature",
    "value": 23.7,
    "unit": "C"
}
```
### В этом случае RuFA Hub выполнит:

```
import module.temperature
module.temperature.mainloop(data)
```
### 🧪 Пример минимального модуля
Файл: ```modules/temperature.py```

```
def mainloop(data):
    temperature = data.get("value")
    unit = data.get("unit", "C")
    print(f"[Temperature Module] Current temperature: {temperature} {unit}")
```
### ⚠️ Важные замечания
Имя файла модуля должно совпадать с "module" из входящего пакета, например:

```data["module"] == "light_control"``` → файл должен быть ```modules/light_control.py```

### Файл должен иметь расширение .py.

Внутри модуля должна быть только одна точка входа — ```mainloop(data)```.

## 🛠 Рекомендации
Используйте логирование вместо ```print()``` для удобства отладки и интеграции с системой логов RuFA Hub.

Обрабатывайте исключения внутри ```mainloop()``` самостоятельно, чтобы не прерывать цикл обработки данных в системе.
